## B-001 / ADR-026 (2026-10-11)

- **The app role cannot write a learner-scoped row.** P1.10's 12 integration tests are green while `persist()` cannot store anything under the role the code runs as, because the suite connects as the table **owner** and an owner is exempt from its own policies (`relforcerowsecurity = false`). `SET ROLE its_platform_app` reproduces the rejection end-to-end through `persist()`: `new row violates row-level security policy for table "diagnostic_results"`. With `SET LOCAL`/`set_config(…, true)` in the transaction the *same* run gets past RLS and fails only at `diagnostic_responses_item_id_fkey` — exactly where the owner path fails, which is what proves the GUC is the whole difference.
- **The GUC's lifecycle (PGlite 0.5.8 and PostgreSQL 15.17, identical; re-confirmed on 16.14):** `NULL` on a session that never set it; `'<uuid>'` inside the transaction that sets it; **`''`** — not `NULL` — after COMMIT and after ROLLBACK; `set_config(…, false)` **survives** COMMIT (a pooled-connection leak). So `''::uuid` raises `invalid input syntax for type uuid: ""`, and ADR-019's "unset ⇒ NULL ⇒ fail-closed" holds only on a virgin connection.
