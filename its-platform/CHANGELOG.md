# Changelog

All notable changes to the ITS Platform API are recorded here.

**Mandate:** `CONSTITUTION.md` §4.4 — *"Every breaking change is recorded in `CHANGELOG.md`
with the migration path before the change merges."* This file is that record. It was
mandated by Constitution v1.0.0 and did not exist until 2026-10-04; the omission was found
while amending §4.4, not by any automated check.

**Format:** [Keep a Changelog](https://keepachangelog.com/en/1.1.0/), versioning per
[SemVer](https://semver.org/spec/v2.0.0.html) as governed by `CONSTITUTION.md` §6.1.

## Unreleased

No released version yet. The platform has never been deployed.

### Changed — breaking

| Change | Migration path | Story |
|---|---|---|
| **Every path moves under `/api/v1`** — `POST /learners/{id}/placement` becomes `POST /api/v1/learners/{id}/placement` | **What broke:** the running application served its 12 routes at the root; it now serves them one segment deeper. The `/health` and `/ready` probes are the declared exception and stay at the root (they are `VERSION_NEUTRAL` and excluded from the prefix — they are consumed by the orchestrator and the gateway, not by API clients). **Who is affected:** any caller that used the root paths. In this repository that set is empty — there is no test that boots the app, no HTTP client, and no IaC that calls the API (verified by search), and the platform has never been deployed, so the cost falls on the contract and the gates rather than on consumers. **What to do:** build the base URL from `servers` in `docs/api-spec.openapi.yaml` (`…/api/v1`) and append the path; no path is renamed, only prefixed. **Since:** this unreleased version. **Correction:** the two entries under *Changed — non-breaking* had claimed this prefix since ADR-012 while `main.ts` contained neither `setGlobalPrefix` nor `enableVersioning`; the claim is now true, and `npm run contract:gate` (rule `prefix`) fails if it stops being true. `iac/kong/kong.yml` routes moved with the application, and its `strip_path: false` went from incidental to load-bearing: the version segment is part of the contract and the gateway must not strip it. | ADR-031 D1, ADR-033 D7, ADR-012 |
| Error responses move from `ErrorResponse` (`{error, message, request_id}`, `application/json`) to RFC 9457 `Problem` (`{type, title, status, detail, instance}`, `application/problem+json`) | Clients branching on the `error` string read `Problem.title`; clients reading `message` read `Problem.detail`; `request_id` is retained as an RFC 9457 extension member. `ErrorResponse` remains declared and `deprecated: true` for the duration of the migration. | P1.17 |
| **The three `/content/*` response schemas are amended to what the content actually declares** | **`LessonContent`**: read `phases[]` instead of `fase1`–`fase4` — each `{phase: 1..4, heading, markdown}`, the lesson's own four authored sections verbatim, materialised by the loader in `lessons.body`; `learner_model` is the parsed `DADOS PARA O LEARNER MODEL` block or `null` (1 of 122 lessons declares none). The removed shape was never produced by anything: `fase4.items[].item_id` had no source in the lesson, and the pack's items are not the phase's (measured: the same lesson's FASE 4 has 2 items against the pack's 7, and the pack's ITEM 1 appears in no phase). **`PackContent`**: `items[].options` loses `minItems: 3` and `items[].key` becomes `null`-able — ADR-004 already declares `options: List[Option]  # Empty for production/minimal-pair items` and `key: Optional[str]  # None for production items`, and 6 of 847 items are exactly that (`scoring = 'asr_phoneme_match'`); `item_type` and `scoring` are added so those 6 are distinguishable from a malformed item; `options[].br_pt_form` and `options[].note` become `null`-able (measured: **all 915** key options in the catalogue are served with `note: null` and 117 of them with a null `br_pt_form`, so the published `type: string` rejected every pack and dialogue response); `listening_items` stays declared and is served as the `[]` ADR-004 declares. **`DialogueContent`**: `status` narrows to `[shipped, shadow_only]` (`withdrawn` describes a *slot*, and the DDL forbids it on a dialogue), `slots[].skill` is the six-value `listening-corpus-spec.md` §4 vocabulary (all six occur), `distractors[].type` becomes nullable with `assessment-item-spec.md`'s six values (`l1_transfer` — the spec's *highest-value distractor* — was used and missing; 126 of 233 non-key options carry prose there). Contract-wide, `cefr_level`'s `'^A[12]\|B[12]\|C[12]$'` becomes `'^(A1\|A2\|B1\|B2\|C1\|C2)$'` (the old pattern anchored only `A1…` and `…C2$` and matched `"B1 garbage"`), and the two `item_id` patterns are **withdrawn**: they were complementary (771 vs 117 of 888 real ids, 0 satisfying both) and were a constraint with no source, which ADR-016 §2 already owns through `identifier_aliases` | Read `phases[]`; treat `items[].key` as optional and branch on `items[].scoring`; stop pattern-matching `item_id` (resolve through `identifier_aliases`). The API is `0.1.0`, unreleased, with no external traffic. Served-from-catalog only: `status = 'shipped'` and `duration_seconds ≥ 45` for a dialogue, and an unknown id or a non-`shipped` dialogue produce the **same** 404 body | ADR-027 §2–§6, P1.12 |
| **`mastery.gate_passed` and its trigger are removed** | A consumer that read `gate_passed` calls the domain gate function, which returns the **full four-clause** predicate: `p ≥ 0.85 ∧ CI₉₅_lower(P) > 0.70 ∧ n_obs ≥ 3 ∧ distinct_days ≥ 2 ∧ spaced_obs ≥ 1`. The old column was `mastery >= 0.85` alone — it dropped the interval conjunct *and* the whole evidence clause that `PRD.md` §6.6, `post-lesson` §7.1 and `curriculum-graph` §6.1 require. **The replacement is stricter, so consumers that relied on the old value may now observe `false`.** That is the correction, not a regression | ADR-018 §1–2, P1.2 |
| **`fsrs_states.retrievability` removed** | Call the domain function: `R(t) = (1 + 0.9803·t/S)^(−0.1542)`. The generated column implemented `exp(−t/S)` — at `t = 10S` it returned ≈0 where the spec mandates **0.693** — and froze the current FSRS parameter set into each row, while `stats` §6.2a refits at 512 pooled reviews. `w_version` is added so a row is attributable to the parameter set that produced it | ADR-018 §3 |
| **`item_responses.bkt_transition` removed** | Nothing replaces it, deliberately. `learned/retained/forgot/guessed` is defined in **no** spec and is not recoverable from a binary outcome — it is a claim about *why* an answer was wrong, which only the learner can make. `item_responses.confidence` already exists and is the honest signal | ADR-018 §9.7 |
| **`learners.cefr_level`, `streak_days`, `xp`, `consent_given_at`, `consent_version` removed** | The band's authority is `DiagnosticRun`. A cached band is stored as a projection carrying `derived_from_diagnostic_id` + `as_of`; a bare `cefr_level` column has no provenance, so a re-diagnostic left a stale value with no way to tell. `streak_days`/`xp` had no basis in any spec (ADR-015 §3). `consent_given_at`/`consent_version` are replaced by append-only `consent_records(learner_id, purpose, version, granted_at, withdrawn_at, legal_basis)` — two columns cannot express purpose-specific, withdrawable consent under LGPD Art. 8 | ADR-015 §3–4, ADR-018 §9.9–9.12 |
| **`lessons.status` split into three columns** | `authoring_state` (`SDD.md` §4's five values) · `publication_state` · `permission_state` (`not_required` / `requested` / `granted` / `refused`). The single column conflated *"does the artefact exist"* with *"may it ship"*, and `permission_state` had no home in any current artefact. `reuse_basis = 'adapt_requires_permission'` records that a lesson *requires* permission, never whether it was *obtained* — so the **48 permission-gated lessons of `PRD.md` §2 carry no fact about their own status**, and §9 M5's exit condition (*"the 13 externally-sourced lessons publish with attribution strings; the 48 restricted ones either hold permission or are excluded"*) cannot be evaluated from the database at all. Original `cite_only` material was equally indistinguishable | ADR-018 §6, §9.12 |
| **`withdrawn` removed from database status vocabularies; `retired` replaces it** | `assessment` §7's *"pulled by defect, retained for audit, not served"* becomes `items.retired BOOLEAN` + `retired_reason`, unifying `SDD.md` §11 with `assessment` §7. `listening_items.status` narrows to `('shipped','shadow_only')`. `withdrawn` survives only in `authoring_state`, meaning *removed* | ADR-018 §6 |
| **Identifier canonicalisation** | Every `skill_id` resolves to `<domain>.<slug>` and every `item_id` to `<prefix>_<skill-slug>_<NNN>` through `identifier_aliases`. Historical spellings — bare (`th_voiced`), short (`lst.gist`), prefix (`pron_th_voiced`), fully dotted (`vocab.tenses.present`, 770 ids) — **continue to resolve**, so `(learner_id, item_id)` rows written before migration keep working. Consumers resolve through the alias table rather than pattern-matching an id | ADR-016 §2, P3.14 |
| **`items.skill_id` → `items.skill_ids TEXT[]` + GIN** | A single FK cannot hold `assessment` §1's `skill_ids[]`. Queries filter on `skill_ids @> ARRAY[…]` | ADR-018 §9.1 |
| **`listening_items` folded into `items`** | Discriminated by `modality = 'listening'` with a nullable `dialogue_id`. One item table, one FK, one FSRS review queue across all five domains — `post-lesson` §3.4 schedules L2 review over Listening, which the old schema made unschedulable | ADR-018 §5, §9.6 |

### Changed — non-breaking

| Change | Notes | Story |
|---|---|---|
| Base URL gains an `/api` prefix: `/v1` → `/api/v1` | Only the `servers.url` entries in `docs/api-spec.openapi.yaml` change. **No path within the API is renamed** — the 9 published paths are unchanged. A client that built its base URL from the server list must re-read it. **Correction (A2, 2026-10-14):** this entry described a change to the *document* only. The running application still served every path at the root, so this row described a state the code did not have; the application half is the breaking entry below. | ADR-012 |
| Local development port `8000` → `3000` | uvicorn's default → NestJS's default. Loopback only. | ADR-012 |
| Global path versioning documented | `docs/api-spec.openapi.yaml`'s `servers` carry `/api/v1`. **Correction (A2, 2026-10-14):** this entry named `app.setGlobalPrefix('api')` + `enableVersioning(...)` as if they existed in `main.ts`. They did not — `main.ts` had neither, and `grep -rn "setGlobalPrefix\|enableVersioning\|VersioningType" src/` returned nothing. The claim was aspirational for as long as it stood, which is a failure mode of this file: a record that is written in advance of the code is indistinguishable from a record of code that exists. Both calls were added in A2 (see the breaking entry below), and `npm run contract:gate` now fails if they disappear. | ADR-012, ADR-033 D7 |
| **`lessons.body` and `dialogues.transcript` materialised by the loader** | ADR-027's persistence half. `lessons.body JSONB NOT NULL DEFAULT '{"phases":[],"learner_model":null}'` holds the four authored `FASE` blocks and the learner-model block — write-once content read whole by one endpoint, so it is a **column, not a `lesson_phases` table**, by the fold criterion of ADR-018 (`packs.manifest` is the precedent, and the schema ADR-022 §1 *rejected* is still rejected). `dialogues.transcript TEXT NOT NULL` holds the authored transcript that `clips` are **derived from**; re-joining it from the clips would be reconstructing a source from its own derivation — a clip keeps one turn's text and a `speaker_id`, so the speaker's name and the authored line structure survive only here. **Neither column is served yet:** the three `/content/*` routes still return mocks, and the response-schema amendment lands in the same ADR's API half, in this same unreleased version. No client is affected by a column | ADR-027 §5, §3b |
| **The three `/content/*` routes serve the persisted catalogue** | P1.12's API half, and the completion of the response-schema amendment recorded under *Changed — breaking* above. `ContentService`/`ContentRepository` read `lessons`/`packs`/`items`/`item_options`/`dialogues`/`speakers`/`voices`/`dialogue_speakers`; **nothing on the request path touches the filesystem**. Two consequences a client can observe without a schema change: a request for a lesson that is not in the catalogue used to return a fixed `{title: 'Sample Lesson', fase1…fase4}` **with 200**, and now returns `404`; and an unknown dialogue id and a dialogue that is not `Status=shipped` return the **same** 404 body, so "not shipped" cannot be probed for. `items`/`item_options` are the only content tables without an `RLS` policy — they are the shared catalog, not learner-scoped — so no learner context is involved on this path | ADR-027 §1–§3, P1.12 |
| **11 listening items became scorable** | `parseSlotTable` read the key marker `✓` from the option table's **value** column only. `corpus/listening-corpus.md` has two generations: **76** rows put `✓` in the value column and **11** put `✓ —` in the trailing column, where the distractor type otherwise sits. Those 11 shipped slots therefore loaded with `items.key IS NULL` and every option `is_key = false`, so **no surface could score them** — diagnostic, shadow CAT or FSRS — and nothing in either repository saw it: `verify-integrity.py`'s **[9]/[11d]/[11e] glob `packs/`**, so `corpus/` is outside every check that would have caught it. The rule is now "the `✓` may sit in either column", and `content-check.mjs` asserts the invariant **two-sidedly**: options ⇔ exactly one key (the 6 ASR-scored minimal-pair items carry no options and legitimately no key — ADR-004: `key: Optional[str]  # None for production items`) | ADR-027 §3a, ADR-004 |
| **BDD auth rate-limit scenario corrected** | `tests/bdd/README.md` claimed the attacker's IP is *"blocked for 15 minutes"* after the 6th request. The chosen stack's built-in `rate-limiting` plugin cannot express a 15-minute window or a block-and-release — its windows are second/minute/hour/day/month/year. The claim is struck: 429 + `Retry-After`, and the window rolls at the minute boundary. A 15-minute ban (custom plugin or WAF rule) is out of scope, tracked in ADR-006's plan (P3). No API change — the BDD text described a gateway capability **no artefact delivered**, which is exactly the false-checkbox disease the ADR-006 audit finding (below) records | ADR-030 §D4, P2.3 |
| **The canonical contract became a parseable document** | `docs/api-spec.openapi.yaml` was Markdown: 862 lines of YAML inside a `yaml` fence, plus the prose around it. Nothing could parse it — not the gate, not an editor, not a generator — and the fact surfaced only when `Object.keys(doc.paths)` over the canonical returned zero paths. It is now bare YAML (body byte-identical to what the fence held, verified by `diff`), and the prose moved to `docs/api-spec.md`. `info.x-contract-provenance` was added in the same pass: the document names the revision of each `specs/*.md` it derived from, and `npm run contract:gate` recomputes those blobs and fails when one moves. Without the pin this drift is undetectable by construction — a spec and the contract derived from it both look correct | ADR-040 D2, D6 |
| **All 14 error responses in the contract declare `Problem`** | Every 4xx/5xx response referenced a schema that did not resolve to `Problem`, and `/learners/{learner_id}/mastery` published no `404` while the obsolete document did — drift in the direction opposite to the one A0 measured. Both are declared now. **Consequence to be aware of:** the document is ahead of the server. The implementation still emits `application/json` with `type: https://httpstatuses.com/{status}` until P1.17, so a client reading the contract would find a media type the running code does not send yet. That gap is A3's, and it is recorded rather than papered over | ADR-034 D4, ADR-040 D5, R6 |

Each clip carries `clip_id`, `sort_index`, `speaker_id`, `voice_id`, `take`, `rate`, `duration_s`, `url`, `expires_at` so the client can fill `slot_responses.clip_id`/`voice_id` with the render it actually played. `rate` is the `1.00` default or the `0.75` accommodation; `ttl_seconds` is the TTL actually used (300). **Added, not Changed**: a new path on a `0.1.0` API that has never been released is not a breaking change (CONSTITUTION §4.4). A trigger covers roles a REVOKE cannot express and cannot be bypassed by the owner; the RLS integration suite and the audit integration suite both assert the trigger's message under the app role **and** the owner | ADR-029, P2.1, P2.2 |
| **`iac/kong/kong.yml`** — the declarative gateway config, plus the `kong:check` gate | BACKLOG P2.3's acceptance (*per-learner 100/min, per-IP 1000/min, enforced at the gateway*) is now **machine-checked, not reviewed**. CI gains a `kong-check` job wired into the `summary` aggregate. **Not deployed** — `deck sync`/Helm/ArgoCD arrive with P2.5; until then this is a static contract gate, the same family as `contract:check`/`domain:check`. **Clients:** no API surface changes; a service behind this gateway will emit `429` (with `Retry-After`) when a window trips | ADR-030, P2.3 |
| **`npm run contract:gate`** — the spec × implementation gate | `scripts/contract-gate.mjs` replaced a 31-line `String.includes` check that could not fail for the reasons the contract exists: it passed on a document with empty `components.schemas`, on a route that no controller implements, and on the drift that mattered — 12 implemented routes against 10 published. The gate now parses the canonical, requires every `$ref` to resolve, `/api/v1` on every `server.url`, `Problem` to carry `type`/`title`/`status`, 4xx/5xx to serve only `application/problem+json`, a `404` on every path-parameter `GET` (another learner's object is 404, never 403), the spec and the controllers to agree in **both** directions method by method, the application to keep applying the prefix, and the provenance pin to match. Route exemptions (`/health`, `/ready`) are declared in the gate, and a **stale exemption fails** — so the list cannot accumulate permissions that no route needs | ADR-040 D5, ADR-031/033 D1/D7, R6 |

### Changed — placement semantics

| Change | Notes | Story |
|---|---|---|
| `placement_provisional` is **derived** from `calibration_status != empirically_calibrated`, never stored as a boolean | It is a property of the evidence, so it clears **by data and never by a date or a flag flip**. The MVP has no rendered audio, so `diagnostic` §2.1.1(4)'s scheduled re-diagnostic does not exist and the label never clears there — which is why `PRD.md` §9 M4's exit condition (*"`placement_provisional` is gone"*) is amended by ADR-017 §5 to *"routing is deterministic, conservative, and its precision is displayed"* | ADR-017 §5, ADR-018 §9.9 |
| The MVP diagnostic is a **fixed 12-item form** (`diagnostic_form_v1`), not a CAT | **This changes the response's precision, and clients must not read θ as a point estimate.** At `a = 1.2`, `SE_stat = 0.481` and `SE_eff ≈ 0.567` → CI₉₅ half-width **±1.11 on θ, wider than the 1.0 gap between CEFR thresholds** (`stats` §3.1). Three independent spec rules already forbade the CAT: `assessment` §2.4 G-Q7 empties the CAT pool (`authored` items barred until `reviewed_by` is set); `stats` §6.2b truncates `elapsed_days` to whole days so an intra-test repeat yields `R = 1.000` and carries no information; and 10 Stage-1 items cannot fill an 18-slot blueprint | ADR-017 §2 |
| Start-node routing is **ordinal and conservative** | `start_cefr` = the **lowest** CEFR band whose θ threshold lies inside `[θ ± 1.96·SE_eff]`. Under-placement, never over-placement — same direction as `stats` §2.1's `P(L₀) = 0.15`. A client that assumed monotonicity in the returned `cefr` must be re-tested: the same θ can now route lower | ADR-017 §3, P1.11 |
| **Listening produces no θ at all** | `diagnostic` §2.1.1(3) already required it; §0 of the diagnostic form has **0 listening items**, so no listening θ is produced, reported or displayed. `curriculum-graph` §4.3's remediation trigger `listening θ < −1.5` was therefore a predicate that **can never be true**, and is substituted by `listening BKT p_know < 0.85` on ≥3 observations. The substitution **weakens** the trigger — BKT is the weaker instrument — and is recorded as such per `CONSTITUTION.md` §9 step 3 | ADR-017 §4 |
| FSRS grade scale is FSRS's native 4-point rating | `post-lesson` §3.2 declared `R = 1 \| 2 \| 3` and §3.3 assigned **correct-immediately → 1**, but FSRS-4.5 derives `S0` from 0.212 / 1.2931 / 2.3065 / 8.2956 in the order where **1 is the worst rating (Again)**. The two scales are inverted and the mapping was never stated. Now: correct-immediately → **4 Easy** · correct-after-hesitation / after-hint / self-corrected → **3 Good** · incorrect-no-hint → **1 Again**. `Hard (2)` is reserved for guided recall and is currently unassigned — recorded, not forced | ADR-018 §4 |

## Deprecation policy

`CONSTITUTION.md` §4.4 governs. Restated here so the changelog is self-contained for a
reader who arrives from a release note.

| Rule | Value |
|---|---|
| **Response headers on a deprecated resource** | `Deprecation: <sf-date>` — RFC 9745 §2.1, value a Date per RFC 9651 §3.3.7, serialised `@<unix-seconds>` — and `Sunset: <HTTP-date>` (RFC 8594), which must not be earlier than `Deprecation`. The scope of the field is the resource in the response's context (RFC 9745 §2.2); a wider scope is documented below |
| **Minimum notice — security and correctness fixes** | 90 days |
| **Minimum notice — feature retirement** | 180 days |
| **Retirement gate** | The `Sunset` date has passed **and** ADR-006 (Kong) access logs show **no external traffic to that prefix for 30 consecutive days**. This metric must already exist when the endpoint is deprecated, not be built afterwards. |
| **Rule for changing a `Sunset` date** | Allowed only in the direction of *later*, and the change is itself a changelog entry with a reason. |

**One of the two gaps this section used to record is closed; the other is not.**

1. **The header form — closed 2026-10-14.** §4.4 used to mandate `Deprecation: true`. RFC 9745 (March
   2025) §2.1 makes the field's value a Date per RFC 9651 §3.3.7 — serialised `@<unix-seconds>` — and
   the boolean was the pre-publication draft form. `CONSTITUTION.md` §4.4 was amended to **v2.2.0** the
   same day; §9 of that document carries the diff, the defect identifier (**H-1**) and the *"what
   weakens"* table, and `docs/adr/033-versioning-deprecation.md` is now **`Accepted`**. Its D5 —
   *"deprecation is announced per whole version, never per endpoint"* — was **withdrawn** in the same
   pass: RFC 9745 §2.2 makes the field apply to *the resource in the response's context*, and the old
   rule had confused the header's scope with the granularity of the 30-day metric below. The previous
   version of this note also cited a *"conventions, not prose"* rule in §4.5; **no such sentence exists
   in §4.5**, and the citation was wrong. `npm run contract:gate` rejecting the boolean now agrees with
   the constitution instead of contradicting it.
2. **The retirement gate has no instrument — open.** The 30-consecutive-day rule needs access logs at the
   gateway, and `iac/kong/kong.yml` configures **no** logging, observability or correlation plugin —
   `grep -iE "http-log\|file-log\|prometheus\|opentelemetry\|correlation"` finds nothing in it. A
   deprecation can therefore be **announced** (`Deprecation` + `Sunset`) but cannot be **retired** on
   evidence. ADR-033 D4 makes the log sink a prerequisite of any retirement.
