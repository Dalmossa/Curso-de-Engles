# Changelog

All notable changes to the ITS Platform API are recorded here.

**Mandate:** `CONSTITUTION.md` §4.4 — *"Every breaking change is recorded in `CHANGELOG.md`
with the migration path before the change merges."* This file is that record. It was
mandated by Constitution v1.0.0 and did not exist until 2026-10-04; the omission was found
while amending §4.4, not by any automated check.

**Format:** [Keep a Changelog](https://keepachangelog.com/en/1.1.0/), versioning per
[SemVer](https://semver.org/spec/v2.0.0.html) as governed by `CONSTITUTION.md` §6.1.

### Added — P2.9 Resilience Patterns on Outbound Calls

| Change | Migration path | Story |
|---|---|---|
| **Circuit Breaker implementation** — Closed → Open → Half-Open state machine with configurable thresholds per service (external_api, database, redis, http, jwks, kong) | Apply `@Resilience()` decorator or use `ResilienceInterceptor` globally. Services automatically get circuit breaker protection. | P2.9 |
| **Retry with exponential backoff + jitter** — Idempotent-only (GET, HEAD, OPTIONS, PUT, DELETE). Non-idempotent (POST, PATCH) only retry on network errors. Formula: `baseDelay * 2^attempt * (0.5 + random())` | Automatic via `ResilienceInterceptor`. Configure per-service in `DEFAULT_RETRY_CONFIGS`. | P2.9 |
| **Explicit timeouts on every outbound call** — Per-service defaults: Kong 5s, PostgreSQL 3s, external APIs 10s, JWKS 5s, Redis 2s | Automatic via `ResilienceInterceptor`. Override with `@Resilience({ timeoutConfig: { timeout: 5000 } })`. | P2.9 |
| **Documented fallback strategies** — CACHE (redis), DEGRADED (database, jwks), DEFAULT (external_api, kong), ERROR (default), CUSTOM | Configured in `DEFAULT_FALLBACK_CONFIGS`. Override via environment variables (`FALLBACK_*_CACHE_TTL`, `FALLBACK_*_LOG`). | P2.9 |
| **Resilient JWKS Verifier** — Circuit breaker + retry + timeout + cached fallback for external OIDC JWKS endpoint. OTel metrics for fetch duration, cache hits/misses, circuit breaker state. | Used automatically when external OIDC configured. Falls back to in-process verifier when no OIDC. | P2.9 |
| **OTel metrics for all resilience patterns** — Circuit breaker state changes, retry attempts/delays, timeouts, fallback activations, operation duration/errors | Automatic — metrics exported via OTel Collector. Query `its_platform_circuit_breaker_state_changes_total`, `its_platform_retry_attempts_total`, etc. | P2.9 |
| **`ResilienceModule` (Global)** — Provides `CircuitBreaker`, `FallbackStrategy`, `ResilienceInterceptor`, and all configs via DI | Import `ResilienceModule` in modules needing resilience. Use `ResilienceInterceptor` for automatic protection. | P2.9 |
| **Decorators** — `@Resilience({ serviceName, operationName, method })` for method-level, `@ResilienceService({ serviceName })` for class-level | Apply to controllers/services needing custom resilience config. | P2.9 |
| **Unit & Integration Tests** — Circuit breaker state transitions, retry backoff/jitter, fallback strategies, full interceptor integration | Run `npm run test:unit -- --testPathPattern=resilience` | P2.9 |

| **Every path moves under `/api/v1`** — `POST /learners/{id}/placement` becomes `POST /api/v1/learners/{id}/placement` | **What broke:** the running application served its 12 routes at the root; it now serves them one segment deeper. The `/health` and `/ready` probes are the declared exception and stay at the root (they are `VERSION_NEUTRAL` and excluded from the prefix — they are consumed by the orchestrator and the gateway, not by API clients). **Who is affected:** any caller that used the root paths. In this repository that set is empty — there is no test that boots the app, no HTTP client, and no IaC that calls the API (verified by search), and the platform has never been deployed, so the cost falls on the contract and the gates rather than on consumers. **What to do:** build the base URL from `servers` in `docs/api-spec.openapi.yaml` (`…/api/v1`) and append the path; no path is renamed, only prefixed. **Since:** this unreleased version. **Correction:** the two entries under *Changed — non-breaking* had claimed this prefix since ADR-012 while `main.ts` contained neither `setGlobalPrefix` nor `enableVersioning`; the claim is now true, and `npm run contract:gate` (rule `prefix`) fails if it stops being true. `iac/kong/kong.yml` routes moved with the application, and its `strip_path: false` went from incidental to load-bearing: the version segment is part of the contract and the gateway must not strip it. | ADR-031 D1, ADR-033 D7, ADR-012 |
| Error responses move from `ErrorResponse` (`{error, message, request_id}`, `application/json`) to RFC 9457 `Problem` (`{type, title, status, detail, instance, request_id}`, `application/problem+json`) | **Both halves have landed (A4, 2026-10-14): the document declares `Problem` on all 14 error responses, and the server now sends it.** `ProblemExceptionFilter` is the only code that builds an error body and the 7 controller throws that hand-rolled `{error, message, request_id}` are plain messages. **Migration path — branch on `Problem.status`, not on `title`:** `type` is `about:blank`, and RFC 9457 §4.2.1 makes `title` the *HTTP status phrase* (`"Not Found"`), not the old `error` code, so a client that used `error` for control flow switches on `status`. A client that read `message` reads `detail`, with three differences: `detail` is a **string** (Nest's validation arrays are joined with `"; "`; per-field structure is ADR-034 D5, `Proposed`), it is **omitted** when it would only repeat the title, and it is **always omitted on 5xx** — §4.3 forbids serialising internals, and the message goes to the log with the correlation id instead. `request_id` is retained, and is now **one id per request** — the same value the `X-Correlation-ID` response header carries on every response (§4.6) — instead of one id per error body. `ErrorResponse` remains declared and `deprecated: true`, referenced by **no** endpoint (measured: the document's only occurrences are its own definition and the comments describing it); its removal and its `Sunset` date are a §4.4-breaking document change, and the date is **not set** — a human decision, recorded in `reports/api/fase-4.md` §8. | P1.17, ADR-034 D6 |
| **The three `/content/*` response schemas are amended to what the content actually declares** | **`LessonContent`**: read `phases[]` instead of `fase1`–`fase4` — each `{phase: 1..4, heading, markdown}`, the lesson's own four authored sections verbatim, materialised by the loader in `lessons.body`; `learner_model` is the parsed `DADOS PARA O LEARNER MODEL` block or `null` (1 of 122 lessons declares none). The removed shape was never produced by anything: `fase4.items[].item_id` had no source in the lesson, and the pack's items are not the phase's (measured: the same lesson's FASE 4 has 2 items against the pack's 7, and the pack's ITEM 1 appears in no phase). **`PackContent`**: `items[].options` loses `minItems: 3` and `items[].key` becomes `null`-able — ADR-004 already declares `options: List[Option]  # Empty for production/minimal-pair items` and `key: Optional[str]  # None for production items`, and 6 of 847 items are exactly that (`scoring = 'asr_phoneme_match'`); `item_type` and `scoring` are added so those 6 are distinguishable from a malformed item; `options[].br_pt_form` and `options[].note` become `null`-able (measured: **all 915** key options in the catalogue are served with `note: null` and 117 of them with a null `br_pt_form`, so the published `type: string` rejected every pack and dialogue response); `listening_items` stays declared and is served as the `[]` ADR-004 declares. **`DialogueContent`**: `status` narrows to `[shipped, shadow_only]` (`withdrawn` describes a *slot*, and the DDL forbids it on a dialogue), `slots[].skill` is the six-value `listening-corpus-spec.md` §4 vocabulary (all six occur), `distractors[].type` becomes nullable with `assessment-item-spec.md`'s six values (`l1_transfer` — the spec's *highest-value distractor* — was used and missing; 126 of 233 non-key options carry prose there). Contract-wide, `cefr_level`'s `'^A[12]\|B[12]\|C[12]$'` becomes `'^(A1\|A2\|B1\|B2\|C1\|C2)$'` (the old pattern anchored only `A1…` and `…C2$` and matched `"B1 garbage"`), and the two `item_id` patterns are **withdrawn**: they were complementary (771 vs 117 of 888 real ids, 0 satisfying both) and were a constraint with no source, which ADR-016 §2 already owns through `identifier_aliases` | Read `phases[]`; treat `items[].key` as optional and branch on `items[].scoring`; stop pattern-matching `item_id` (resolve through `identifier_aliases`). The API is `0.1.0`, unreleased, with no external traffic. Served-from-catalog only: `status = 'shipped'` and `duration_seconds ≥ 45` for a dialogue, and an unknown id or a non-`shipped` dialogue produce the **same** 404 body | ADR-027 §2–§6, P1.12 |

| **The API requires an authenticated caller** | **What broke:** every request to a published path used to be answered, to anybody. `CONSTITUTION.md` §4.5 makes a `JwtAuthGuard` registered globally with `@Public()` opt-outs mandatory, and A0 measured the state this entry ends: **zero** `@UseGuards` in `src/`, so *deny by default* was false and the default was **allow**. ## Deprecation policy

`CONSTITUTION.md` §4.4 governs. Restated here so the changelog is self-contained for a
reader who arrives from a release note.

| Rule | Value |
|---|---|
| **Response headers on a deprecated resource** | `Deprecation: <sf-date>` — RFC 9745 §2.1, value a Date per RFC 9651 §3.3.7, serialised `@<unix-seconds>` — and `Sunset: <HTTP-date>` (RFC 8594), which must not be earlier than `Deprecation`. The scope of the field is the resource in the response's context (RFC 9745 §2.2); a wider scope is documented below |
| **Minimum notice — security and correctness fixes** | 90 days |
| **Minimum notice — feature retirement** | 180 days |
| **Retirement gate** | The `Sunset` date has passed **and** ADR-006 (Kong) access logs show **no external traffic to that prefix for 30 consecutive days**. This metric must already exist when the endpoint is deprecated, not be built afterwards. |
| **Rule for changing a `Sunset` date** | Allowed only in the direction of *later*, and the change is itself a changelog entry with a reason. |

**One of the two gaps this section used to record is closed; the other is not.**

1. **The header form — closed 2026-10-14.** §4.4 used to mandate `Deprecation: true`. RFC 9745 (March
   2025) §2.1 makes the field's value a Date per RFC 9651 §3.3.7 — serialised `@<unix-seconds>` — and
   the boolean was the pre-publication draft form. `CONSTITUTION.md` §4.4 was amended to **v2.2.0** the
   same day; §9 of that document carries the diff, the defect identifier (**H-1**) and the *"what
   weakens"* table, and `docs/adr/033-versioning-deprecation.md` is now **`Accepted`**. Its D5 —
   *"deprecation is announced per whole version, never per endpoint"* — was **withdrawn** in the same
   pass: RFC 9745 §2.2 makes the field apply to *the resource in the response's context*, and the old
   rule had confused the header's scope with the granularity of the 30-day metric below. The previous
   version of this note also cited a *"conventions, not prose"* rule in §4.5; **no such sentence exists
   in §4.5**, and the citation was wrong. `npm run contract:gate` rejecting the boolean now agrees with
   the constitution instead of contradicting it.
2. **The retirement gate has no instrument — open.** The 30-consecutive-day rule needs access logs at the
   gateway, and `iac/kong/kong.yml` configures **no** logging, observability or correlation plugin —
   `grep -iE "http-log\|file-log\|prometheus\|opentelemetry\|correlation"` finds nothing in it. A
   deprecation can therefore be **announced** (`Deprecation` + `Sunset`) but cannot be **retired** on
   evidence. ADR-033 D4 makes the log sink a prerequisite of any retirement.
